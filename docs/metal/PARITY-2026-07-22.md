# CUDA ↔ Metal parity evaluation (2026-07-22, post upstream/master merge)

Merge `df34c67` brought `metal` to parity with upstream/master @ `aecfc80`
(7 commits: per-request thinking across 3 API shapes, unified max_tokens
8192, `--ctx auto` arch-margin fix, 4 docs commits; README resolved to ours
per policy — the arms keep separate READMEs).

## Inherited by the merge — verified on the Metal lane

The v0.3.2–v0.3.5 tool-call hardening series lives in the **shared
headers**, and the Metal server is on those exact call paths:

- **Tool-drift recovery modes 10/11/12/12b + mostly-escaped content** —
  all in `api_common.h::parse_bare_tool_calls`; Metal calls it at 5 sites
  (chat/messages/responses, stream + non-stream + wrapper-less recovery).
- **Fence-skip guard + streaming stray-close strip** (`stream_split.h`) —
  Metal includes it via `stream_format.h`; `test_metal_stream` exercises it.
- **ChatML-injection sanitizer** (`strip_ctrl.h`) — via `tool_preamble.h`.
- Upstream host tests `test_tool_drift`, `test_think_resolve`,
  `test_stream_split` compile with plain g++ on macOS and **all PASS**
  (verified 2026-07-22). They are NOT yet wired into `make test-cpu`.

## True parity gaps (Metal lacks, ranked)

1. **Per-request thinking on `/v1/responses`** — Metal honors
   `enable_thinking`/`chat_template_kwargs` on chat completions and
   `thinking:{type}` on Anthropic messages, but the Responses branch never
   parses it (found during the v0.6.0 G8d triage: reasoning cannot be
   disabled per-request on Responses). Upstream's `fee3b27` added the
   shared resolver in `api_common.h` (with `test_think_resolve`); Metal
   keeps its own per-endpoint parsing. Fix: adopt the shared resolver at
   Metal's 2–3 parse sites (also deletes the duplicated logic). Small.
2. **Unified `max_tokens` default 8192** — Metal's per-endpoint defaults
   are still the pre-v0.4.0 256/256/1024/4096 (completions, chat, messages,
   responses; `metal_server.cpp:2146/2250/2569/2931`). The
   `Q27_METAL_MAX_TOKENS_DEFAULT` knob exists but ships unset — pi clients
   (max_tokens:null) truncate mid-answer out of the box. This was the exact
   production incident that motivated upstream's unify. Fix: one-line per
   call site, or set 8192 as the fall-through. Small.
3. **`--ctx auto` measured-free sizing** — upstream sizes the window from
   measured free VRAM with an arch-scaled safety margin (~254K ctx on a
   24 GB card) and splits it across `--slots N`. Metal has **no auto
   sizing at all**: the default is a constant `--ctx 8192`
   (`metal_server.cpp:1729`). On a 24 GB Mac the official tier fits far
   more; every user currently has to know to ask. Fix: Metal equivalent
   using `MTLDevice.recommendedMaxWorkingSetSize` / current allocated size
   minus model + KV-per-token. Medium (the KV-per-token math already
   exists for the admission budget).
4. **API-key auth on serving endpoints** — upstream v0.4.0 has opt-in
   Bearer-key auth covering API access. Metal has the admin token
   (mutating routes only); serving endpoints are unauthenticated
   (127.0.0.1 default binding is the mitigation). Gap matters only for
   multi-tenant/LAN serving. Small-medium (port the upstream check).
5. **q4s tier (4.55 bpw)** — CUDA-side repack tier for VRAM-starved cards;
   nothing in `src/metal/` knows the dtype. On Metal the small-memory
   answer is T2/bonsai, so this is a *tier-coverage* note rather than a
   serving gap. Large if ever wanted (backend matmul coverage).
6. **nll `step_with` + input guards** (v0.3.1 fix program) — engine.cu
   side; Metal's `--nll-long` was written bucket-compatible and passed the
   v0.6.0 gate, but the specific input-validation guards should be
   eyeballed once. Trivial.

## Architectural divergences (not gaps)

- **Continuous batching** (CUDA v0.2.0, `conductor.h`) vs Metal **multislot**
  (per-slot engines, FIFO admission, disk prefix snapshots). The 5090
  4-stream ceiling measured ~250 t/s at 2 lanes; the M4's unified-memory
  bandwidth makes slot-count economics different. Divergence is deliberate.
- **Multi-stream decode aggregation** — same story, CUDA-architecture
  feature.
- **sm_86/sm_89/sm_120 kernel ladders, graph-zoo, gcache** — GPU-arch
  specifics, N/A to Metal.
- **llama-benchy / thunderdome harnesses** — cross-engine benchmark rigs;
  usable as-is against the Metal server (HTTP), nothing to port.
