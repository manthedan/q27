 A. Bugs / Correctness issues

 A1 — MEDIUM — teacher_force_logits{,_wide} leaves x1_ stale after advancing position_.
 src/metal/metal_engine.cpp:1589-1591 and :1640-1652:

 ```cpp
   backend_.copy(*clogits_, (uint64_t)(count - 1) * VOCAB * sizeof(float),
                 *logits_, 0, (uint64_t)VOCAB * sizeof(float));
 ```

 Only the logits row is made coherent (codex fix, 2026-07-15). x1_ — the hidden row capture_state/save_state persist — still
 describes the pre-pass token while position_ += count has moved on; mtp_round does copy cfinal_ → x1_ for exactly this reason
 (:1365). Latent today (the --kl-kv/--chunk-parity drivers never snapshot), silent state corruption the day someone snapshots
 after a teacher-forced pass. Fix: mirror the cfinal_ last-row copy into x1_.

 A2 — LOW — divergent early-exit before threadgroup barriers in the 128-thread turbo kernels.
 q27_kernels.metal:3548 (q27_turbo_wht), :3565, :3679, :3742:

 ```metal
   if (head >= args.heads || j >= 128) return;   // ... then turbo_butterfly() barriers
 ```

 j >= 128 is per-thread divergent; the butterfly and reduction barriers below are only well-formed because every dispatch is
 exactly 128 threads (metal_backend.mm:1714, 1736, 2285, 2336). A future 256-thread dispatch under-populates the barriers (UB,
 not a wrong-number bug). Fix: drop the j >= 128 clause and static-check the dispatch width host-side.

 A3 — LOW — dispatch-implicit threadgroup geometry in reduction kernels (silent-wrong-result class if a constant changes).
 - q27_kernels.metal:974 (+ twins at :3485, :3644, :3833): merge tree hardcodes 8 simdgroups (for (uint offset = 4; ...)); a
   128-thread dispatch would read never-written tg_m/tg_acc — garbage, not a guard failure.
 - :795 and :3151: for (uint block = simdgroup; block < blocks; block += 8) — strides assume 8 simdgroups; fewer skips
   activation blocks (unquantized garbage), more is benign.
 - :3318: reduce_sum(..., 8) literal in q27_l2norm_rows while q27_l2norm_heads uses args.groups.
 - metal_backend.mm:1661: topk dispatches 1024 threads with no maxTotalThreadsPerThreadgroup check (fine on every Apple GPU;
   unguarded).
   All correct at current dispatch constants. The repo's own recorded lesson ("any kernel with a width-gated fast path needs a
   gate that enters it", packed-dot scale incident) argues for host static asserts. Fix: one assertion per site, or read
   threads_per_threadgroup in-kernel.

 A4 — LOW — q27_embedding_*_dev comment is wrong in justification, right in conclusion.
 q27_kernels.metal:722-724:

 ```
   // A corrupt id past the vocabulary reads garbage, never out of bounds
   // (argmax only writes ids < n).
 ```

 A corrupt id would read out of bounds (wi = token[0]*cols + gid with no clamp); safety rests entirely on the argmax invariant,
 which today holds (argmax emits only < n; mask+argmax degrades to id 0). Fix the comment to state the invariant as the
 load-bearing fact.

 A5 — LOW — q27_matmul_t2_mm_h header comment describes a different (rejected) kernel.
 q27_kernels.metal:1760-1764:

 ```
   // ... flushes run per 32-K sub-slab (the x-scale group) ...; flushes run
   // per 16-K sub-slab, so partials are integer sums bounded by 16*127 = 2032
   // — always exact in half.
 ```

 Self-contradictory leftover of variant B's rejected half-accumulator design; the shipped structure is two 32-K
 float-accumulator sub-slabs folded per 64-K tile. Code is correct (gated bit-identical); the justification text is stale. Fix
 comment.

 A6 — LOW — "Same serial encoder … order dispatches" misstates the ordering mechanism.
 metal_backend.mm:323, :370, :1285, :1389:

 ```objc
   // Same serial encoder: the merge reads the partials the first
   // dispatch wrote; serial compute encoders order dispatches.
 ```

 Dispatches in one encoder are not implicitly ordered by the encoder; the actual guarantee is Metal's default per-resource
 hazard tracking (MTLHazardTrackingModeTracked, default for every buffer used here, mmap wraps and private scratch included).
 Conclusion right, justification wrong — and silently wrong the day someone sets MTLHazardTrackingModeUntracked as a "perf
 experiment", since every batched layer chain and both GQA merge dispatches ride on it. Fix: correct the comment at all four
 sites.

 A7 — LOW — dead reduction helper and write-only args field.
 q27_kernels.metal:21 reduce_row() has no callers; MatvecArgs.simdgroups is set to 8 at every host site and read by no kernel.
 Hygiene; remove or wire.

 A8 — LOW — stale validation message.
 metal_backend.mm:2029: "chunked embedding requires 1..12 tokens" — the cap has been 96 since wide chunks
 (EmbedRowsArgs.tokens[96], ABI 7). Behavior right, message wrong.

 A9 — LOW — matvec_pair/matvec_f16_pair_rows don't validate cols % 4 for packed_half4.
 metal_backend.mm:973-995, :2126-2151; kernel q27_kernels.metal:76-78 vector-loads packed_half4. Production shapes (5120) are
 fine; an odd synthetic F16 tensor is a misaligned-load fault rather than a host error. Host validation gap, one-line check.

 No race, barrier-ordering, bounds, or integer-exactness defects found in the production GEMV/GEMM/attention/GDN paths. The
 exactness claims that exist hold: Q4/Q8 lane dots ≤ 32·127·127 = 516,128 < 2²⁴ (:1190), T2/B1 ≤ 4,064, MMA slabs ≤ 64·127·127
 ≈ 1.03 M < 2²⁴. Clamped-row compute/drop-store conventions are consistent in every tiled kernel. q27_delta_chunk's top-of-loop
 barrier correctly separates iteration t's part reads from t+1's writes; q27_conv_chunk/q27_delta_chunk in-place src==dst is
 safe (register-staged per thread).

 B. Robustness / resource issues (host)

 B1 — MEDIUM — snapshot save is not durable: no fsync before rename.
 metal_engine.cpp:674-680:

 ```cpp
   if (fflush(f) != 0 || fclose(f) != 0) { ... }
   if (rename(tmp.c_str(), path.c_str()) != 0) ...
 ```

 write-tmp+rename gives rename atomicity, not content durability. A crash after rename can leave a file with full i_size but
 unflushed (zero-filled) pages: load_state's two-pass validation checks lengths and total size, all of which still match, so a
 structurally-valid, zero-content snapshot loads silently — GDN/KV state zeroed, generation continues degraded. Fix:
 fsync(fileno(f)) before close and fsync the directory after rename.

 B2 — MEDIUM — position_ advances at encode time; a mid-batch GPU error leaves the engine torn.
 metal_engine.cpp:923 (position_++; inside encode_token) vs step()/prefill ordering: the CommandBatch::finish() that would
 surface the error runs after position_ was bumped. On MTLCommandBufferStatusError the KV rows and GDN commits of that token
 may never have executed, but the engine reports them consumed; a caller that catches the throw and reuses the engine (the
 server does per-request) continues from inconsistent state. mtp_round/suffix_round/oracle_round order it correctly (position_
 += encoded after batch.finish(), e.g. :1372). Fix: advance host position only on successful finish, or codify "engine is
 unusable after a backend throw — restore or destroy" at the engine level.

 B3 — MEDIUM — load_state pass 2 never re-validates blob lengths (TOCTOU).
 metal_engine.cpp:753:

 ```cpp
   snap_read(f, &stored, sizeof stored, path);
   for (uint64_t off = 0; off < bytes; off += stage.size()) { ... }
 ```

 Pass 1 validated stored == bytes per blob; pass 2 re-reads stored and ignores it, streaming bytes into live GPU buffers
 regardless. A file swapped between passes (snapshot dir is user-writable) restores unvalidated content. Fix: if (stored !=
 bytes) throw in pass 2.

 B4 — LOW — gqa_partials monotonic growth, never shrunk. Confirmed known: metal_backend.mm:306, :348; assigned with per-engine
 move + G6 re-accounting (tasks/mini-e2-gqa-partials.md; triage B1/E2/C3). At 96-wide chunks and 262K ctx the sizing is ~609
 MB; G6 charges the ×2 realloc-transient peak today.

 B5 — LOW — bench allocations live in the production backend object. dr_xt_scratch (grown lazily on roofline arm d/2 calls,
 metal_backend.mm:1260), mma_roofline_k_p per-cols PSO map, attrib_dummy — all held until ~MetalBackend. No production dispatch
 reaches them; footprint is trivial but the surface is bench-only in a production binary (triage E10 → Homebrew lane,
 confirmed).

 B6 — LOW — fixed_state_bytes() undercounts a constraint-heavy server. metal_engine.cpp:496-524 omits mask_pool_ (fully
 populated: 64 × 31,040 B ≈ 2.0 MB, metal_engine.cpp:243), wide_head_stage_ (240 KB), and top-k staging (~8 KB) despite its own
 "≥ 1 MB class" comment — mask_pool_ crosses that class. Small G6 admission hole.

 B7 — LOW — attrib_dummy allocation unchecked. metal_backend.mm:2331: 4-byte private buffer, setBuffer:nil on failure crashes
 the instrument path instead of throwing.

 B8 — LOW — ~MetalEngine underflow guard is debug-only. metal_engine.cpp:235: assert(...); under NDEBUG a future double-return
 bug wraps cache_bytes silently. Clamp + log instead (cannot throw from a destructor).

 B9 — confirm — abort_commands discards the uncommitted buffer; no cancel API exists (triage B5: [command cancel] is not a real
 API; contract comment landed). finish_command error path resets command/batching before throwing, and CommandBatch's
 destructor covers every mid-batch C++ exception — no wedge state found. ObjC descriptor temporaries in the ctor are
 ARC-balanced (not leaks).

 D. Numerics / contract observations

 D1 — MEDIUM — activation quantization diverges from the CUDA reference by construction: division vs reciprocal-multiply.
 q27_kernels.metal:798, :1125, :3154:

 ```metal
   int q = scale > 0.0f ? int(rint(v / scale)) : 0;
 ```

 vs src/kernels.cu:117-118 (also :153-154, :546-547):

 ```cuda
   float inv = s > 0.f ? 1.f / s : 0.f;
   int q = __float2int_rn(v * inv);
 ```

 Both round-to-nearest-even, but v/scale (one rounding) vs v*(1/scale) (two) differ by ≤1 ulp of quotient, which flips the
 rounded integer at exact .5 boundaries — a full activation quantum (amax/127) on the input of every Q4/Q8 projection on the
 official tier, decode and chunk. This is a per-element input difference, not the documented accumulation-reorder class; the
 Metal unit gates' CPU references divide too, so both suites are blind to it, and the 16-token byte-exact gate can't see a
 rare-event class. Mathematically Metal's form is better; parity says match the reference (or move the reference) and quantify
 via the envelope instrument. Wrong by parity, right by arithmetic — both stated.

 D2 — LOW — softplus mid-window residue vs CUDA log1pf.
 q27_kernels.metal:1010-1011, :3220-3221 vs src/blocks.cu:133. The 2026-07-15 codex fix restored the flush tail (exp(value)
 below −16); in the remaining window [−16, 20] Metal computes log(1.0f + exp(value)) where CUDA computes log1pf(expf(x)) —
 worst-case ≈ 6e-8 absolute on softplus (not the flush class; both gate kernels affected identically). MSL has no log1p; fix if
 wanted via a two-term series for e < 2⁻¹⁶, else document acceptance.

 D3 — LOW — RoPE theta at depth. Formula and operand order are expression-identical to CUDA (q27_kernels.metal:880, :3333 vs
 src/blocks.cu:62-64), so no cross-backend shift by construction; but both backends evaluate cosf/sinf at up to 262,143 rad in
 float, and no gate isolates rope-phase error from KV-codec error at depth (32K NLL/needles are end-to-end). Distinct from
 KV-codec P1's RoPE-pair allocation simulation. Observation only; see E8.

 D4 — LOW — NLL protocol mixes a third reduction regime for the tail row.
 Chunked rows: float GPU q27_nll_rows (q27_kernels.metal:3403, 256-thread tree). Leftover single row: double CPU nll_cpu
 (metal_engine.cpp:1504-1510, :1552-1560). CUDA runs all rows float in k_nll_rows with a 1024-thread tree
 (src/blocks.cu:910-944). One row per pass in a different precision and reduction than both the rest of the pass and the
 oracle. Fix: route the tail through nll_rows at rows=1 (backend accepts ≤12).

 D5 — verified parity inventory (no action). Attention scale 1/sqrt(256) both (engine.cuh:887 vs metal_engine.cpp:858); GQA kvh
 = qh/gqa and per-head decode kernel ↔ GQA kernel qh = kvh*gqa+sg consistent with spec3.cu; DeltaNet expansion tile (h%16,
 VERIFY-1's assumed semantics, Q27_GDN_HEAD_TILE=1); delta recurrence expression-for-expression identical including
 part[0]+part[1]+part[2]+part[3] order (blocks.cu:236-273 vs :1036-1076); conv oldest-first matches Q27_CONV_OLDEST_FIRST=1; L2
 norm rsqrt(max(Σx², eps²)) matches ggml semantics (blocks.cu:45); gated-norm multiply order identical; rope sections
 [11,11,10,0] + freq_base 1e7 enforced at load; argmax lowest-index tie rule matches CUDA am_pack (blocks.cu:401-412);
 embedding unscaled row lookup; MTP wiring (concat embedding-first, own KV cache, shared_head_norm, output_q4→output fallback)
 matches SPEC; ssm_a-sign/softplus/beta/sigmoid gating matches.

 D6 — confirmed documented tolerance classes (no action). Chunk GEMM 3e-4 tolerance (K-tile float reorder; weight side
 integer-exact; activation rounds once at staging) and its MTP low-margin divergence class ("is known"/"serves" entry +
 envelope instrument). GQA blocked kernels deterministic but not bit-equal to per-head kernels; the straddle split
 (metal_backend.mm:2366-2377 + kernel live_blocks math) preserves chunk↔decode bit-parity — verified, including the
 block-indexed partial-liveness identity. One under-documented member: the T2/B1 tier's chunk path consumes int8-quantized
 activations (gdn_chunk → matmul_quantized) while its serial path advertises "exact ternary math, no activation quantization"
 (project() float route) — same envelope family, worth one line in METAL_PROGRESS so the "exact" claim stays scoped to serial
 decode.

 D7 — LOW — reduction-tree differences are reorder class. Metal 256-thread two-level simd_sum trees vs CUDA 1024-thread
 warp+block trees (rmsnorm, NLL); rsqrt vs rsqrtf (both ≤2 ulp approximations) feeding every norm. Inside the measured
 chunk-vs-serial envelope (max|Δlogit| ≤ 0.7).

 E. Suggested missing roadmap items

 Checked against docs/plans/*, METAL_PROGRESS "Active work" and "Known debt", and the 2026-07-17 triage outcomes — none of
 these duplicate them (excluded as already-covered: KV-codec P1 steps, envelope ensemble, official-tier timing legs,
 resident-greedy/cross-tier re-measures, 3090 build-width docs, model-free multislot stress suite, slot cancel/prefix-affinity,
 chatml tool parity, forced-engagement gate, oracle multi-position probes, BaseRT probes 2–3, E2 partials move, E6 GEMV leg,
 E10 bench-PSO/Homebrew, GPU-sampling stage 3, suffix round-up-to-tile).

 - E1 — P1 — Activation-quantize operand-order parity leg (from D1). Move the three Metal quantize sites to the CUDA
   formulation (v * (1.f/scale)) or vice versa, with a pre-registered --envelope leg on the official tier to size the class;
   update the two CPU test references in lockstep so the suites keep their ability to fail.
 - E2 — P2 — Snapshot durability (from B1). fsync snapshot content before rename (+ directory fsync); add a crash-consistency
   leg to tools/snapshot_gate.sh (kill between rename and fsync; load must fail loud, never silently).
 - E3 — P2 — Teacher-force hidden-row coherence (from A1). Copy the last cfinal_ row to x1_ in both teacher-force paths,
   mirroring mtp_round; extend --chunk-parity to assert hidden-row equality so the fix is gated.
 - E4 — P2 — Post-throw engine-state contract (from B2). Advance host position_ only on successful batch completion (or
   document destroy/restore-after-throw), plus one failpoint gate injecting an end_commands error and asserting position/state
   semantics. Distinct from the queued fake-backend scheduling suite: this is engine-level GPU-error recovery, not fairness.
 - E5 — P3 — NLL tail-row protocol unification (from D4). One-row nll_rows dispatch for the leftover token; keeps the whole
   pass in the CUDA-matched float regime.
 - E6 — P3 — Threadgroup-geometry assumption guards (from A2/A3). Host static asserts (or kernel threads_per_threadgroup
   guards) for the 8-simdgroup merge trees, the block += 8 quantize strides, the literal-8 reduce_sum, the 128-thread turbo
   kernels, and the 1024-thread topk dispatch.
 - E7 — P3 — G6 accounting completion (from B6). Charge mask_pool_, wide_head_stage_, topk staging in fixed_state_bytes, or
   write down the exclusion bound.
 - E8 — P2 — RoPE theta-precision probe at depth (from D3). Double-precision reference vs both backends at ≥100K positions;
   isolates rope-phase error from the KV-codec P1 workstream's per-pair allocation question.
 - E9 — P3 — Hygiene batch. load_state pass-2 length re-check (B3), attrib_dummy nil check (B7), stale "1..12 tokens" string
   (A8), dead reduce_row/simdgroups removal (A7), ~MetalEngine assert → clamp+log (B8), cols % 4 validation in the F16 pair
   entries (A9), "serial encoder" → hazard-tracking comment corrections (A6), q27_matmul_t2_mm_h comment rewrite (A5).

 Read of the tree: the kernel layer is in unusually good shape — barrier placement, clamp conventions, integer-exactness
 bounds, and the straddle/parity contracts all verified clean; the strongest open item is D1 (a real, unmeasured Metal-vs-CUDA
 per-element divergence on the official tier's hot path), and the strongest host items are the snapshot durability and
 post-throw engine-state contracts (B1/B2), both silent-state-corruption class with small fixes.
