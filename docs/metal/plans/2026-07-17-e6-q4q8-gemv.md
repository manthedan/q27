# E6 — Q4/Q8 GEMV efficiency leg (official tier), pre-registered

Date: 2026-07-17. Status: PLANNED, not run. Origin: metal audit
2026-07-17, finding E6 — the audit's one genuinely new workstream
(docs/metal/plans/2026-07-17-metal-review-triage.md). Bench first with
pre-registered bands; kernel work only if the bench funds it.

## Motivation

The audit claims the official tier's dominant decode cost — the Q4_G64 /
Q8_G128 quantized matvec family — runs at 67–90 GB/s effective while the
T2 select-form kernel reaches ~93 GB/s on the same machine after its two
funded rewrite rounds. Neither T2 trick (select-form inner-loop
restructure, half-MMA staging) has been tried on Q4/Q8. If the claim
holds at the low end there is a ~25% decode-wall win sitting on the
table for the ~17 GiB tier; if the current kernels are already near the
machine's demonstrated stream ceiling, the workstream dies here for the
price of one bench run. The existing `--dtype q4q8` table is not this
instrument: it times a flat shape list with uniform 1.0 scales (no
correctness gate can see a scale bug — the vacuous-scale lesson), no
per-token mix weighting, and no verdict.

## The measurement leg

New `--official` mode in `tools/metal_gemv_bench.cpp`, mirroring
`run_b1_probe`'s structure (correctness gates before any timing, banded
verdict printed by the harness, not eyeballed from a table).

**Shapes = the official-tier per-token production projection mix**, the
same eight-shape geometry as the b1/slot2 probes (metal_engine.cpp
weight shapes; counts: 48 GDN layers, 16 attention layers, 64 FFN, 1
head) with the official vocab and the real v1.3 dtype policy
(tools/repack.py `policy()`): every matrix weight Q4_G64 except attn_k/v
(Q8, KV-persistence promotion) and the output head (Q8; official vocab
151936).

| shape | dtype | per-token count |
|---|---|---|
| ffn gate/up [17408x5120] | Q4_G64 | 128 |
| ffn down [5120x17408] | Q4_G64 | 64 |
| gdn qkv [10240x5120] | Q4_G64 | 48 |
| gdn gate [6144x5120] | Q4_G64 | 48 |
| ssm/attn out [5120x6144] | Q4_G64 | 64 |
| attn q [12288x5120] | Q4_G64 | 16 |
| attn k/v [1024x5120] | Q8_G128 | 32 |
| output head [151936x5120] | Q8_G128 | 1 |

Excluded, stated in the output: the MTP draft layer (blk.64.*, Q8) and
the `output_q4.weight` draft-head copy — both stream only on draft
rounds, and this leg measures the serial production token; gdn
alpha/beta (~0.15% of per-token bytes, dispatch-overhead-dominated, same
exclusion as the slot2 probe).

**Arms per shape**: the current production kernels exactly as serial
decode dispatches them — `matvec_quantized` single, and
`matvec_quantized_pair` on the ffn gate/up sibling pair (two distinct
synthetic tensors, the cache-honesty rule from the flat table).
**Reference arm, same run**: the T2 select-form float matvec
(`backend.matvec`, the production T2 decode kernel) on the T2 projection
mix — the machine's demonstrated stream ceiling on this exact dispatch
pattern (~93 GB/s expected). We divide by a same-run measured number,
never by the spec-sheet 120 GB/s: theoretical peak is not reachable by
any GEMV dispatch, and the question is whether Q4/Q8 matches what a
kernel on this machine has already proven achievable.

**Correctness gates before any timing** (a candidate that only times is
not a candidate): synthetic Q4/Q8 tensors with NONUNIFORM
exactly-representable fp16 scales (0.5..2.0 step 0.25, the (r·31+g)%7
pattern from the b1 leg) against a CPU double dequantize·dot reference.
The quantized-activation arm gates against its own exact int8 activation
model (the c3-popcount pattern: integer math mirrored on the CPU), and
its distance to the float reference is reported, not gated (activation
quantization cost is a property of the path, not a bug). Bound 1e-3 max
rel with the sum|x| denominator floor; anti-vacuity: nonzero and
row-distinct output.

## Pre-registered decision metric and bands

**Metric: R = byte-weighted per-token aggregate effective GB/s of the
official mix on the current kernels ÷ same-run T2 select-form aggregate
GB/s.** Per-shape table and per-token wall ms (with implied
at-parity tok/s) are reported alongside; R decides.

- **R ≥ 0.90 → KILL the rewrite.** Even perfect parity buys ≤ 11% wall;
  below the cost of a kernel round plus regate — T2's two funded rounds
  both started from > 20% headroom.
- **0.80 ≤ R < 0.90 → conditional.** No full round. Fund a targeted fix
  only if the per-shape table shows a single mix-dominant shape (≥ 20%
  of per-token bytes) below 0.75 of the reference — name it in RESULTS.
- **R < 0.80 → fund exactly one rewrite round**, gated by re-running
  this leg; the round's own ship line is R ≥ 0.90 after rewrite.

The audit's own numbers (67–90 GB/s vs ~93) span R ≈ 0.72–0.97 — all
three bands are reachable, so the bench discriminates rather than
confirms.

## Rewrite candidates IF funded (out of scope for this doc)

- **Select-form restructure** (T2 round-1 pattern): one
  conditional/arithmetic accumulate per element on the decoded nibble
  with per-group correction, cutting inner-loop decode ALU.
- **Half-MMA staging** (T2 round-2 pattern): dequantize to half through
  threadgroup memory, drive simdgroup MMA for the dot.
- Pair-kernel widening (x2 family) only if the per-shape table indicts
  the pair dispatch specifically.

## Machine and protocol rules

Quiet 24 GB M4 for the timing run (house rule; correctness gates are
contention-tolerant and can run any time). Synthetic tensors only — no
model load, but still a GPU run: orchestrator-owned, staged and launched
only on explicit go. Default 20 reps per shape on the existing
clock-ramp warmup. Timing and verdict land in this file's RESULTS
section plus a chronicle entry either way — a kill is a result.

## RESULTS (2026-07-16 night, quiet 24 GB M4, the operator's go)

**R = 0.716 → FUND ONE ROUND** (official mix 52.44 GB/s byte-weighted ÷
same-run T2 reference 73.24 GB/s). The audit's 67–90 GB/s claim lands at
its low end. Correctness gates: single and pair kernels match their CPU
int8-activation models on all 8 shapes ≤ 1e-3 max rel (nonuniform fp16
scales); float-reference distance reported (activation-quantization
property, not gated).

Per-shape ratios (q GB/s ÷ same-shape T2): ffn gate/up pair 0.731 at
43.9% of per-token bytes — the mix-dominant target; ffn down 0.814;
worst offenders attn q **0.517** and ssm/attn out **0.572**; output head
0.889; attn k/v 1.251 (Q8 beats the tiny-shape float reference — not a
rewrite target). Per-token GEMV wall 263.07 ms (3.8 tok/s GEMV-bound);
at reference parity 188.35 ms (5.3 tok/s) — a ~1.4× serial-decode prize
before MTP multiplication.

Funded round (registered, NOT started): one rewrite round on the Q4
matvec family — T2's select-form restructure and half-MMA staging are
the candidate patterns, the pair kernel and the small-rows shapes
(attn q, ssm/attn out) the first targets. Ship line: **R ≥ 0.90 on this
leg re-run**, byte gates green. Kill line: if the round lands < 0.90 it
ships nothing and the tier keeps the current kernels.
