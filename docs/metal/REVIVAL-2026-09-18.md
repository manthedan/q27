## Decision in brief

Revive the **small-Mac native inference engine and experimental agent**, not the
old merge-back campaign. Start a new integration branch from pinned current
upstream, then restore deliberately selected fork-only features. Preserve the
old branches as references; do not merge the entire historical fork blindly.

First model milestone: **Bonsai 2 text inference, correct against Prism's
reference runtime, on the base M4**. Use the PQ2_0 pack first; treat dense
PTQ1_0 packing, accelerated prefill, and speculative decoding as later,
separately measured milestones. Neither the new model nor this integration is
implemented by this reconnaissance.

## Bonsai 2: what changes technically

Sources checked September 18:

- [Prism announcement](https://prismml.com/news/bonsai-2-27b)
- [GGUF model card](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf),
  observed revision `6ed5e12bf84b7a63069882c91dd9e9218647d17b`
- [Prism reference runtime](https://github.com/PrismML-Eng/llama.cpp/tree/1a07bfa5f4144274c8f1c9963821dd9d9a51854b),
  pinned `prism` branch source for this audit

Bonsai 2 is based on **Qwen3.8-27B**, with the same advertised backbone
architecture, not the old Qwen3.6 Bonsai checkpoint. The card reports
Apache-2.0 licensing, 262K native context, and these language-model packs:

| Pack | Reported size | Encoding | Initial role |
|---|---:|---|---|
| `Ternary-Bonsai-2-27B-PQ2_0.gguf` | 7.21 GB | 2-bit slots, g128 | First correctness target |
| `Ternary-Bonsai-2-27B-PTQ1_0.gguf` | 5.95 GB | Dense base-3, g128 | Later footprint/performance experiment |

These are **weight sizes, not process memory**, and 262K is not a measured
usable context on this Mac. Prism's quality-retention and speed figures are
vendor results, not q27 measurements. The announcement and current model card
also present different benchmark breakdowns; do not combine their tables.

### The critical difference: rotated weights

The new card declares block-1024 Hadamard rotation with fixed signs. Packed
weights are in a transformed basis; the runtime must transform activations.
**Renaming the new dtype to the old T2 format is not sufficient.**

The pinned reference implementation provides the contract:

- `ggml/include/ggml.h`: **PQ2_0 = 142**, **PTQ1_0 = 143**. Old type 42 is
  now group-64 Q2_0 in this source, whereas q27's legacy repacker forges type
  42 as group-128. Never infer compatibility from the old type name alone.
- `ggml/src/ggml-common.h`: PQ2_0 is a 34-byte block (FP16 scale plus 32 code
  bytes). PTQ1_0 is 28 bytes: **24 `qs` bytes + 2 `qh` bytes + FP16 scale**.
  q27's parked T3 format is a different layout; do not alias them.
- `src/llama-model.cpp:1196–1335`: versioned `prism.hadamard.*` metadata,
  transform/block/axis validation, explicit sign vectors, tensor allowlists,
  optional grouped GDN-value ordering, inverse-lookup tensor names.
- `src/llama-graph.cpp:1546+`: optional GDN permutation, signs, then
  normalized Hadamard before the affected matrix multiplications.
- `src/llama-graph.cpp:2426+`: embedding lookup uses the **inverse** order:
  Hadamard, then signs. Apply it only when declared by metadata.

q27's current repacker copies architectural/name fields but **does not retain
`prism.hadamard.*`**. New conversion must preserve and validate that contract;
unsupported or incomplete rotation metadata must fail closed. A new explicit
model-policy/version should keep legacy unrotated Bonsai distinguishable.

No new GGUF weight payload was downloaded in this audit. Actual tensor types,
rotation lists, sign vectors, grouped-GDN flag, vocabulary/template, and MTP
presence still need inventory from the pinned artifact. Do not substitute the
model card or backbone shape check for that inventory.

### Correctness before resurrecting old speed claims

Current upstream deliberately disables Bonsai chunked prefill: its chunk GEMM
quantizes activations while Bonsai's serial path retains float activations
(`src/metal/metal_engine.cpp`, constructor and `set_chunked_prefill`). The old
fork's ~47 tok/s T2 prefill result is **not a license to enable that path for
Bonsai 2**. Add rotation-correct float-activation batching only after serial
reference parity, with numerical and task-quality gates.

The old [T3 experiment](plans/2026-07-15-t3-packing.md) lost on M4 because
unpacking became instruction-bound despite fewer bytes. The new checkpoint
and reference kernels justify a new measurement, not automatic reversal of
that result. Keep the permanently closed B1/T2 byte-graft thesis closed.

## Upstream changes worth inheriting

**Priority 0 — model fidelity and agent behavior**

- Qwen3.8 rendering/dialect/assistant-history fixes and template goldens.
- September tokenizer fixes: added-token matching for tool tags, newline
  handling, Unicode classes/NFC, reference parity tests.
- Current streaming parser/router, drift corpus, multi-call and
  reasoning-channel tool recovery. These need testing through the **Metal
  server and native agent**, not only CUDA's server test harness.
- Tokenizer BPE cache: assess on local prompts after correctness is pinned.

**Priority 1 — reliability and useful interfaces**

- Current Metal serving/admission/snapshot/recovery contracts and httplib
  compatibility fixes; avoid overwriting them with historical whole files.
- Sampling semantics and request defaults: audit Metal separately. Upstream's
  CUDA sampler advances are not automatically implemented by Metal's
  `src/sampling.h` path. Bonsai's current card gives thinking defaults
  `temperature=1.0, top_p=0.95, top_k=20, min_p=0.0`; do not copy the older
  upstream Qwen3.8 `min_p=0.05` recipe indiscriminately. Non-thinking mode
  additionally needs the advertised presence penalty or an explicit limitation.
- Request capture/replay and cache measurements, borrowing concepts where the
  implementation remains CUDA-specific.

**Not automatic Metal ports**

CUDA graph families, paged KV/concurrent batching, FP4 MMA, DFlash2, and MTP
speedups are not prerequisites for Bonsai 2. A compatible trained draft model,
acceptance, runtime/memory cost, and implementation are separate questions.
Inherit upstream CUDA code unchanged; do not expand this project into a CUDA
optimization effort.

## Proposed implementation sequence and exit gates

1. **Clean revival baseline.** Create a durable sibling worktree/new branch
   from `0f1f1d49`, leaving the dirty checkout and donor branches intact.
   Inventory retained product features in a checklist. Restore the native
   agent, TUI, instrumentation, and packaging as focused commits with their
   tests; reconcile shared APIs semantically, never via blanket file restores.
   Preserve research branches independently of what gets enabled by default.
2. **Model contract/repack.** Pin the source revision, source/runtime commits,
   checksums, tokenizer and template. Inventory the actual GGUF; add tiny
   synthetic PQ2_0 and rotation-metadata fixtures. Prove packed-value/scale
   round trips, reject wrong group sizes and unsupported rotation contracts,
   and ensure old B1/T2/q4s loading still passes.
3. **Serial Bonsai 2 Metal.** Implement CPU-reference and Metal transform
   tests, including inverse embedding and declared GDN ordering. Cover every
   affected projection, especially output/FFN-down/SSM-out. Compare
   teacher-forced logits and layer probes with the pinned Prism runtime on
   identical tokens; predeclare tolerances. Plausible generated text alone
   is not a correctness gate. Validate no-MTP behavior if confirmed by the pack.
4. **Useful local agent.** Validate fresh tokenizer/rendered prompts and XML
   tools, thinking, cancellation, context limits, and sampling through both
   native agent and HTTP routes. Run small coding/tool tasks and record memory,
   first-token latency, prefill and decode on the **base M4**. Invalidate or
   version old caches/sessions when tokenizer/rendering semantics change.
5. **Performance, independently.** Correct batched prefill first; then price
   dense PTQ1_0 versus PQ2_0 at equal model semantics. Use the recovered benches
   and kernel-agent harness with noise-floor controls. Speculation is optional,
   not part of the first working-model definition.
6. **Product release.** Add a distinct Bonsai 2 registry/profile entry without
   replacing legacy packs. Re-run relocated tarball/Homebrew tests, verified
   pull, native-agent persistence and serving recovery gates. Publish only
   after model-backed evidence; no release is implied by this audit.

Resource rule: model/GPU jobs run **one at a time**. This machine reports
Apple M4, 24 GiB unified memory; the historical secondary target is an M4
16 GiB mini, not re-contacted here. Local `models/` uses ~66 GiB and has the
old Bonsai controls but no Bonsai 2 pack. Free disk observed ~106 GiB. Do not
download an FP16 model or run two resident reference engines concurrently.
