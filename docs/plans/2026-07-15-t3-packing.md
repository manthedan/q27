# T3 native ternary packing (whitepaper item 2)

Base-3 packing of the ternary tier: 5 trit-codes per byte (243 ≤ 256), 26
bytes per 128-column group, scales unchanged. **1.75 bpw effective vs
T2_G128's 2.125 — an ~18% cut in decode weight-stream bytes.** At the
bandwidth bound this is a direct ceiling move (~12.4 → ~14+ tok/s resident;
their fork lists this as future work — landing it first extends the edge).

## T3_G128 format (dtype id 5)

- Group 128 columns; per group **26 bytes**. Byte `b`, slot `j` (0..4) holds
  the code for column `b*5 + j` while `b*5 + j < 128`; byte value =
  `c0 + 3*c1 + 9*c2 + 27*c3 + 81*c4`, codes `c ∈ {0,1,2}` decode to
  `(c-1)*scale` exactly as T2. Byte 25 carries columns 125–127 in slots 0–2;
  slots 3–4 MUST be code 1 (trit 0) — canonical padding, so all bytes are in
  [0, 242] and repacks are bit-reproducible.
- Row data = `(cols/128) * 26` bytes; scales fp16 `[rows, cols/128]`
  unchanged from T2. Same tensors ternary as bonsai-t2-v1; meta
  `quant_policy: bonsai-t3-v1`.
- Decode LUT: 243-entry table, entry = 5 × 2-bit codes (10 bits used); the
  select-form dot then runs unchanged on 2-bit codes.

## Phases (each gated; kill cheaply if Phase 0 disappoints)

0. **Synthetic kernel bench.** `q27_matvec_t3_g128` (float-activation
   select-form, byte-per-lane schedule: lane-strided bytes, 5 y-loads per
   byte shared across the simdgroup's 4 rows, per-byte scale from L1) into
   `metal_gemv_bench` next to T2. Gate: CPU-reference parity on random
   trits AND effective GB/s / implied tok/s beating the T2 kernel by ≥10%
   on the [17408, 5120]-class shapes. If the LUT decode makes it
   instruction-bound, record and stop.
1. **Repack + loader.** `tools/t2_to_t3.py` (streaming numpy: q27 → q27,
   T2 blobs re-coded base-3, dtype 4→5, policy bonsai-t3-v1, md5 manifest;
   hard-fail on code 3, canonical padding enforced). Loader/`inspect`:
   dtype 5, size validation `rows*(cols/128)*26`. Gate: full-artifact
   roundtrip — T3 decode == T2 decode trit-exact on every tensor.
2. **Remaining kernels.** `q27_matmul_t3_mm` (chunk GEMM staging moves to
   128-column slabs: Wt 32×128 + Xt 128×16 + Sc = 26 KB threadgroup, one
   scale per slab), `q27_embedding_t3{,_rows}`. Backend dispatch on dtype.
   Gates: CPU-reference parity each; T2↔T3 cross-parity within FP
   tolerance (summation order differs by design).
3. **Engine + artifact.** validate_architecture accepts bonsai-t3-v1
   (ternary matrix dtype parametrized), repack the real 6.66 GiB artifact
   (→ ~5.5 GiB). Gates: `--validate-only`; `make test-metal` green; greedy
   16/32/48 committed tokens vs the T2 artifact (expect identical; any
   divergence gets the low-margin-token analysis before acceptance); 2K
   NLL spot vs T2 (≤0.1% PPL delta); suite + codex autoreview.
4. **Measure.** `metal_decode_bench --dtype t3` resident ceiling and
   artifact tok/s, back-to-back with T2 at matched thermal state
   (protocol rule). Ledger + plan-doc results.

## Phase 0 verdict (2026-07-15): KILLED — decode-bound, parked

Back-to-back synthetic bench at matched thermal state, 40 reps
(`metal_gemv_bench --dtype t2|t3`): **T2 88–98 GB/s effective (ffn_gate
0.247 ms/op) vs T3 ~48–54 GB/s across four kernel variants (ffn_gate
0.392 ms/op) — 55–60% slower wall despite 18.75% fewer code bytes. FAIL
against the ≥10% win gate.**

Variant attribution:
- v1 byte-per-lane, constant-memory LUT: 49.2 GB/s (divergent constant
  gathers serialize — but fixing that barely moved it).
- v2 threadgroup-memory LUT + T2-style four-groups-in-flight with uniform
  scales: +6%.
- v3 mask-free full-byte loop + packed_float4 activation loads: flat.
- v3b pure-ALU base-3 decode (mul-shift div-3 chains, zero memory): 24
  GB/s — 2× worse; the LUT gather beats arithmetic decode.
- v4 word-aligned uint weight walk (4 bytes = 20 columns per load): flat.
  (Also surfaced: odd group counts make rows word-misaligned — the kernel
  now falls back to a scalar byte walk for odd-nb shapes.)

Root cause: T2's select-form GEMV at 93–97 GB/s is already at the M4's
practical stream bound with **zero decode** — its 2-bit codes are the
select masks. Base-3 inserts a dependent per-byte gather + bit extraction
into that loop; the kernel becomes decode-ALU-bound around 50 GB/s and the
byte savings are irrelevant. The whitepaper's §9 "future work" framing
survives contact: on Apple Silicon this packing needs a fundamentally
different decode (bit-plane splits, or CUDA where LOP3 changes the
arithmetic) — not a LUT in front of the same dot.

Disposition: kernel, dtype plumbing, wide-shape gate (CPU reference + T2
cross-parity, odd-nb scalar path), and the bench mode stay in-tree as the
reproducible parked experiment. No repack tool, no engine wiring, no
artifact carries dtype 5.

## Non-goals

CUDA T3 kernels (Metal first, as with the tier itself); binary 1.125-bpw
tier (own plan: `2026-07-15-binary-tier.md` — note binary has **no packing
analog to T3**: 128 code bits + 16 scale bits per g128 is already
information-theoretically dense for {−1,+1}, so T3's ~18% cut is
ternary-only and the two streams don't compete for kernel surface); sub-2-bit
KV (separate instrument — the KL gate).

## Risks

- LUT decode cost: T2 spends ~2 ALU ops/element on shift-mask; T3's LUT
  lookup + shifts may push the GEMV off the bandwidth bound (Phase 0 kills
  this cheaply if so).
- Prefill chunk GEMM decode overhead grows (35 decodes/thread vs 16):
  prefill is compute-bound already; a modest chunk-rate regression is
  acceptable and recorded, not hidden (item 3 tracks prefill levers
  separately).
- Argmax flips from summation-order change: greedy gate in Phase 3 measures
  this directly instead of assuming.
