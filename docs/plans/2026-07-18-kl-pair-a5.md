# A5: KL(mixed ‖ official) cross-model paired-logit gate — pre-registration (2026-07-18)

Review-2 (2026-07-18-expert-review-2-triage.md §1, §8) adopted the A0–A7
sequence. A5 is the decisive quality gate for the mixed-pack serving thesis:
**KL(mixed ‖ official 17 GiB) < KL(T2 ‖ official)** must hold on the
pre-registered corpora, or the mixed pack's NLL recovery is not translating
into distribution-level fidelity against the model we would actually ship
against.

## Why a new driver

`--kl-kv` is a same-model KV-precision comparator: one `Shared` mapping,
two engines that differ only in the KV store path, lockstep teacher-forced.
A5 is **cross-model**: two independent artifacts (mixed pack and official),
each with its own `Model` mapping, `MetalBackend` queue, weight wrap, and
residency set. The lockstep machinery (12-token `teacher_force_logits`
chunks, per-position `q27::forward_kl` on CPU in double precision, bucketed
report) is reused unchanged; only the engine-construction half changes.

The tokenizer is byte-identical across all tiers (verified: the same
`models/qwen36-27b-mtp/qwen36-27b-mtp.tok` loads every artifact in the
census and serving stacks). No cross-tokenizer alignment is needed; position
`i` in model A's stream corresponds to position `i` in model B's.

## Driver shape

New top-level CLI flag, rides the `--nll FILE --nll-long N` input path:

```
q27-metal-cli --kl-pair MODEL_A MODEL_B --nll tokens.bin --nll-long 8192 \
              --tokenizer models/qwen36-27b-mtp/qwen36-27b-mtp.tok \
              --ctx 8192
```

- Two `MetalEngine::Shared` mappings opened in the same process:
  `open_shared(MODEL_A)` and `open_shared(MODEL_B)`.
- One engine per mapping, both fp16-KV (the KL is a *weight* comparison;
  the KV codec is held at the cleanest setting so it cannot confound).
- Both engines advance in lockstep over the same token stream in
  12-token chunks; per-position forward-KL is computed on CPU in
  double precision exactly as `--kl-kv` does.
- Positions must match across engines: chunk boundaries identical,
  `teacher_force_logits` calls paired, no resets.

Mutual exclusions: `--kl-pair` is its own instrument. Drop `--kl-kv*`,
`--kv`, `--chunk-parity`, `--envelope`, `--save-state`, `--load-state`,
`--tokens`, `--prompt`, `--validate-only`, `--dump-logits`,
`--temperature/--top-p/--top-k/--seed`, `--mtp/--suffix/--oracle`,
`--prefill`.

## Memory budget

The M4 holds both mappings simultaneously:

| Artifact | Bytes (approx) |
|---|---|
| official 17 GiB | 17,727,348,224 |
| mixed ~4.1 GB | ~4,400,000,000 |
| KV caches + partials (2 engines × 8K ctx) | ~0.5 GB |
| Metal driver, queues, staging | ~0.5 GB |
| **Total** | **~23 GiB** |

This is tight against 24 GiB physical. The driver:

1. **Refuses to start** if `MODEL_A == MODEL_B` (vacuous, self-KL is a
   different instrument: `--kl-pair-self` below).
2. **Refuses to start** if the sum of the two file sizes plus a 1 GiB
   overhead allowance exceeds the host's physical memory — fail loudly,
   not OOM.
3. Prints a per-mapping residency line at startup so the log captures
   what was actually wired.

The mini cannot run this (16 GiB < 17 GiB official alone). A5 is
M4-only.

## Pre-registered gates

### Plumbing gates (must pass before any measurement)

- **G1 (unit):** `forward_kl` unit battery — KL(p,p) = 0, KL ≥ 0,
  agreement with naive softmax reference, asymmetry sanity. (Already
  exists from `--kl-kv`; must still pass.)
- **G2 (self-KL plumbing):** `--kl-pair MODEL MODEL --nll tokens.bin
  --nll-long 256` must produce KL = 0.0 exactly at every position
  (two engines on the *same* mapping, one fp16 each, lockstep — any
  nonzero means position/chunk misalignment, not numerics). Hard stop
  on nonzero.
- **G3 (sabotage both ways):** two controls must give the expected
  sign:
  - `--kl-pair T2 T2` → KL = 0 (plumbing, same as G2 but on a real
    tier artifact).
  - `--kl-pair T2 B1` → KL > 0 at every position (two different
    models; a zero here means the driver is not actually reading the
    second artifact).

### Measurement gate (the ship/kill line)

Run on the standing 8K wikitext NLL corpus **and** on an 8K held-out
code corpus (A4's code requirement folded in per the operator's call):

```
--nll data/wikitext-2-raw-8k.tokens --nll-long 8192
--nll data/code-holdout-8k.tokens    --nll-long 8192
```

For each corpus, three runs:

1. `KL(T2 ‖ official)` — reference
2. `KL(mixed ‖ official)` — candidate
3. `KL(B1 ‖ official)` — floor

**Ship line:** `KL(mixed ‖ official) < KL(T2 ‖ official)` on BOTH
corpora, with the per-position paired bootstrap 95% CI on
`KL(mixed) − KL(T2)` excluding 0 from below.

**Conditional:** the CI includes 0, or the ordering holds on only one
corpus — report, the operator decides.

**Kill:** `KL(mixed ‖ official) ≥ KL(T2 ‖ official)` on either corpus
with CI excluding 0 from above — the mixed pack's NLL recovery is not
translating into distribution-level fidelity; the A1/A2 lone-arm
recoveries are endpoint-overshoot artifacts (R2's WiSE-FT/task-
arithmetic caveat) and the mixed-pack serving thesis closes.

### What we do NOT claim

A KL win here does not prove the mixed pack is *better* than T2 in
absolute terms — only that it is closer to the official 17 GiB
reference than T2 is. The capability battery (A6) remains the
conjunctive gate.

## Implementation notes

- `--kl-pair-self MODEL` is the G2 plumbing arm (same mapping, two
  fp16 engines). Reuses the `--kl-kv-self` internals where possible;
  the flag exists so the plumbing gate does not require two mappings.
- Bucketed report: same edges as `--kl-kv` (0–2k / 2k–8k / 8k–16k /
  16k–32k) plus overall mean, tail quantiles (p50/p90/p99/p99.5/max),
  and run-length structure at 0.1/0.5 nats — the tail is the
  graduation metric, not the mean (kv-codec step-1 finding).
- The paired bootstrap CI lives in a small post-processor (Python or
  awk) over the per-position KL dump; the driver writes
  `--kl-pair-out FILE` with one KL per line per position for each
  corpus × arm.

## Non-goals

- On-policy KL (own generations), sub-2-bit KV experiments, GPU KL
  reduction, CUDA parity — all follow-ups, same as `--kl-kv`.
- This does NOT replace the NLL census publication or the capability
  battery; it is the third leg of the A5/A6 conjunctive gate.

## Open items before the measurement

- Held-out code corpus selection: needs to be disjoint from the
  wikitext corpus and from any training data we know is in Bonsai's
  mixture. Candidate: a slice of `the-stack-smol` or a local code
  corpus the operator designates. **Operator decision required before
  the measurement run.**
- The mixed pack itself: assembled by `tools/q27_mix.py` from the
  census-winning classes. If A0–A3 have not yet identified a winner,
  A5 blocks on them. (The driver can be authored and plumbed in
  parallel — the measurement cannot run until A3 composes a candidate.)
